# Runtime image vulnerability assessments

Reviewed 2026-10-27; all exceptions expire **2026-11-27**. The HIGH/CRITICAL gate remains enabled, including unfixed findings. `.trivyignore.yaml` matches individual CVEs against the exact Debian package/version/architecture PURLs observed in the pinned Bookworm image. There are no npm, global severity, source-package wildcard or permanent exceptions. A changed package PURL or expired assessment reopens the gate. Reports retain suppressed findings with `--show-suppressed`.

## Remediation before assessment

Both runtime images remove bundled npm/yarn (including their vulnerable transitive tooling packages); neither server needs a package manager. API dependencies omit development and optional peer packages, including the Prisma CLI and TypeScript. The API still contains its compiled generated client and production adapter/runtime dependencies.

Both images remove unused mount/umount/nsenter/blkid/findfs/lsblk/infocmp/GNU-gzip command entry points and strip SUID/SGID bits. The unchanged Node 24 Debian runtime does not dynamically link libacl, libblkid, libmount or libtinfo. Compose drops capabilities and sets no-new-privileges for API/web. Production launch instructions use the same restrictions. No external disk probing, mounting, terminal-database parsing, Perl archive handling or privileged ACL workflow is part of these servers.

The API smoke test asserts absent tooling, expected dynamic links, no SUID/SGID files, non-root execution and working HTTP/database/Kafka behavior. Browser tests exercise the final web image. These checks bound the assessment; this is not a claim that all installed Debian source packages have upstream fixes.

## Reassessment

The maintainer must review these entries before expiry and after base-image, application/native-dependency or runtime-privilege changes. Remove an entry when its package is fixed/removed. If affected functionality becomes reachable, fix/remove it or fail the gate; do not extend an entry solely to make CI pass. Never run these runtime images privileged or add host devices/fstab mounts as an assumed deployment convenience.

Scanner versions and image digests are pinned in CI. The local report may show more raw OS findings than accepted gate findings because multiple binary packages inherit one source-package CVE. Preserve the full JSON evidence and the image digest. Repository security scanning does not establish security certification or a production deployment's security posture.
